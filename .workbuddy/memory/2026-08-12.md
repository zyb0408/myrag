## 脚本调试：macOS bash 3.2 + set -u 多字节 bug
- 现象：`merge-to-main.sh` 报 `TARGET_BRANCH: unbound variable`，但变量明显已用 `${VAR:-default}` 赋值。
- 根因：macOS 自带 bash 为 3.2.57。**`set -u`（nounset）下，对「含中文(多字节) + 多个 `$变量` 的双引号字符串」做词法展开会误报 unbound variable，且报错变量名是乱指的**（同一处有时报 TARGET_BRANCH、有时报 CURRENT_BRANCH）。与单引号无关。
- 验证：去掉单引号/改 【】/ 先赋值给变量再传，均无效；只有去掉 `set -u` 才彻底解决。
- 结论：写跨版本 bash 脚本时，macOS 上**不要依赖 `set -u`**。改用显式校验（`die` / `[ -n ]` / `${VAR:-default}`）保证安全，只保留 `set -o pipefail`。
- 修复文件：`/Users/yingbin/Desktop/claudecode/knowlege-new/merge-to-main.sh`（`set -uo pipefail` → `set -o pipefail`）。
